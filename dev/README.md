# Локальный стенд и тесты

Всё запускается из корня проекта через `dev/run.sh`.

| Команда | Что делает |
|---|---|
| `dev/run.sh setup` | один раз: `npm install` в `dev/` и `backend/`, Playwright для Python с Chromium |
| `dev/run.sh up` | собирает сайт и поднимает всё в фоне (логи в `dev/.logs/`) |
| `dev/run.sh ui` | интерфейс: «Сегодня», «План» и редактор, журнал, база упражнений, модель плана |
| `dev/run.sh sync` | вход, токены устройств, синхронизация двух устройств, экран входа, блокировка Neon → прокси |
| `dev/run.sh down` | остановить |

Нужны Node 22.18+ (запускает `.ts` без сборки), Python 3 и Playwright.

## Что поднимается

| Порт | Что |
|---|---|
| 8765 | сайт из `docs/` |
| 5433 | Postgres в памяти (PGlite) |
| 8790 | заглушка Neon Auth: `/__test/otp?email=…` — последний код, `/__test/expire?email=…` — истечь сессии |
| 8791 | настоящая функция `backend/src/index.ts` поверх этой базы |
| 8792 | SQL для тестов: `curl -d "select …" localhost:8792` |
| 8793 | прокси `relay/api/relay.ts`, как на Vercel |
| 8794 | «Neon из Беларуси»: 403 без CORS на всё |

Тесты подключают приложение к стенду через `localStorage['upg3~apiOverride']` — строку или список адресов.
UI-тесты включают `upg3:noLogin`, чтобы не мешал экран входа. Скриншоты — в `dev/shots/`.

Тесты печатают результат, а не падают: смотри строки `ok` / `FAIL`, `errors: []`, `48 ok, 0 failed`.
Тесты синхронизации ждут чистую базу, поэтому `sync` перезапускает стенд перед каждым.

## Остальное

- `dev/tests/live_check.py` — проверка живого сайта (экран входа, связь с сервером), без входа.
- `dev/stack/q.mjs` — SQL к боевой базе: `DATABASE_URL=… node dev/stack/q.mjs "select key, updated_at from app.kv"`.
